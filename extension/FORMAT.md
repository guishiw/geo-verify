# 导出文件格式：`geo-verify-capture/1`

浏览器辅助插件在用户点击“保存为文件”时，在本机生成一个 UTF-8 编码的 JSON 文件。
本文件约定它的字段；`geo-verify collect --adapter share` 按此格式导入，导入后的观测通道为 `browser_assist`。

虚构示例：[`examples/capture.example.json`](examples/capture.example.json)（域名均为 `.example`）。

## 总体规则

- 字段集合与顺序固定，见下表；插件不会写入表外的字段。
- **未填写的项一律为 `null`**，不编默认值：文本项留空（或只有空白）、三态项选“未知”，导出都是 `null`。
- 文本项只去掉首尾空白，内部的换行与空白原样保留。回答文本（`messages` 中 `assistant` 一条）完全原样保存，不做任何处理。
- 编号项（`platform`、`window_id`、`query_id`）填了就必须符合观测契约的编号写法
  `^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`，否则插件拒绝导出并指出是哪一项。
- `synthetic` 只出现在示例文件里，表示虚构数据；插件导出的文件不带该字段。

## 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `format` | 字符串 | 固定为 `geo-verify-capture/1`。格式有不兼容的变化时才改版本号。 |
| `capture` | 字符串 | 固定为 `browser_assist`：浏览器辅助、由用户主动点击保存。 |
| `saved_at` | 字符串 | **保存时间**：用户点击“保存为文件”时的本机时间，换算为 UTC，ISO 8601 写法，精确到秒（毫秒截断，不进位），如 `2026-10-08T02:00:00Z`。它不是提问时间，也不是回答生成的时间；插件不会伪造或推算采集时间。 |
| `url` | 字符串 | 读取时页面的地址（浏览器报告的当前地址）。 |
| `title` | 字符串或 `null` | 读取时页面的标题；为空时为 `null`。 |
| `platform` | 字符串或 `null` | 平台编号，用户手工填写。 |
| `window_id` | 字符串或 `null` | 时间窗口编号，用户手工填写。 |
| `query_id` | 字符串或 `null` | 题目编号，用户手工填写。 |
| `messages` | 数组 | 恰好两条，顺序固定：先 `user`，后 `assistant`。 |
| `sources` | 数组 | 选区内的链接，规则见下文；没有链接时为空数组。 |
| `model` | 字符串或 `null` | 模型或产品版本，用户手工填写；页面上看不到版本时留空，改填入口特征。 |
| `environment` | 对象 | 采集环境，字段见下表。 |
| `operator` | 字符串或 `null` | 采集人，用户手工填写。 |
| `synthetic` | 布尔 | 只在示例文件中出现，值为 `true`。 |

`messages` 的每一条：

| 字段 | 说明 |
|---|---|
| `role` | `user` 或 `assistant`。 |
| `content` | `user`：用户手工填写的实际提问原文（必填，为空时插件拒绝导出）。`assistant`：用户在页面上选中的回答文本。 |

`environment`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `entry_form` | 字符串 | 固定为 `web`（在浏览器网页端采集）。 |
| `entry_features` | 字符串或 `null` | 入口特征，如“网页端默认模式”；模型版本未知时用它描述入口。 |
| `logged_in` | 布尔或 `null` | 是否登录：是 `true`、否 `false`、未知 `null`。 |
| `history_cleared` | 布尔或 `null` | 是否清除历史：三态，同上。 |
| `web_search` | 布尔或 `null` | 被测产品回答时是否联网检索：三态，同上。（插件本身从不联网。） |
| `region` | 字符串或 `null` | 地域，用户手工填写。 |
| `device` | 字符串或 `null` | 设备，用户手工填写。 |

## 链接（`sources`）

每一项为 `{"url": ..., "title": ...}`：

- 只收集与用户选区相交的 `<a href>` 链接；选区整个落在一个链接里面时，收集这个链接。选区以外的链接不读取。
- 按地址**去重**，保持首次出现的顺序。地址按浏览器给出的原样保存（只去首尾空白），写法不同的地址
  （如多了 `#片段` 或查询参数）视为不同链接，不做合并或改写。
- `title` 为链接文字，连续空白压缩为一个空格并去掉首尾空白；为空时为 `null`。同一地址出现多次时，取第一个非空的链接文字。
- 只保存 `http` / `https` 地址；`javascript:`、`data:`、页面内按钮等其他链接不保存，弹窗预览里会说明忽略了几个。
- 插件不访问这些链接，也不核实它们是否可达；它们只是用户选区内出现过的链接。

## 文件名

`geo-capture_<平台编号>_<时间窗口>_<题目编号>_<保存时间>.json`，例如
`geo-capture_engine-a_W1_Q001_20261008T020000Z.json`。没填的段省略；每段只保留英文字母、数字和 `. _ -`
（其他字符换成 `-`，连续标点合并，首尾不留标点，每段最多 40 个字符）。文件名只为方便归档，导入时以文件内容为准。

## 导入

```sh
geo-verify collect PROJECT --adapter share --input geo-capture_engine-a_W1_Q001_20261008T020000Z.json \
  --platform engine-a --window W1 --query Q001
```

导入按 `capture` 字段识别出这是浏览器辅助采集的文件，观测通道记为 `browser_assist`；
文件里的 `saved_at` 是保存时间，导入时应如实标注为保存时间，而不是提问时间。
