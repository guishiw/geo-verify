# 浏览器辅助插件（MV3）：保存所选回答

geo-verify 的采集辅助工具。在网页端人工采集时，用户自己在页面上提问、自己选中回答文本，
再点击插件把**选中的文字和其中的链接**连同手工填写的采集信息保存为本地 JSON 文件，之后用
`geo-verify collect` 导入为观测。

## 用途与边界

- **只在用户主动点击时保存其选中的内容和链接**：打开弹窗不读取页面；点“读取所选内容”时才读取一次当前活动标签页上的选区；没有选区时提示“请先在页面上选中要保存的回答”，不读取整页。
- **不自动提问、不自动翻页**：不填写页面上的输入框，不点击、不提交、不滚动页面，没有定时器或页面变化监听，不在后台运行（清单里没有后台脚本，也不向任何页面自动注入脚本）。
- **不联网**：插件代码里没有任何网络请求，不加载远程脚本、样式、字体或图片；选区里的链接只记录地址，不访问。导出文件用 Blob 在本机生成。
- **不绕过任何访问限制**：只读取用户在浏览器里本来就能看到并亲手选中的内容；没有代理、账号、验证码、反检测或伪装浏览器特征的逻辑，不读取 Cookie 或网页存储。
- 权限只有两项：`activeTab`（用户点击插件时，临时允许访问当前这一个标签页）和 `scripting`（在该标签页执行一次只读的读取函数）。
- 时间如实记录：文件里的 `saved_at` 是用户点击保存时的本机时间（**保存时间**，换算为 UTC），不是提问或回答生成的时间。
- 插件输出的是采集记录，只用于预检；不代表任何平台的态度，也不对平台结果作任何保证。

## 安装（加载已解压的扩展程序）

1. 打开基于 Chromium 的浏览器的扩展管理页（在地址栏输入 `chrome://extensions`，其他浏览器为各自的扩展管理页）。
2. 打开右上角的“开发者模式”。
3. 点“加载已解压的扩展程序”，选择本仓库的 `extension/` 目录。
4. 需要时把插件固定到工具栏。

`extension/tests/` 下的文件只用于在 Node 里运行测试，弹窗和清单都不引用它们。

## 使用

1. 照常在被测平台的网页上提问，等回答完整显示。
2. 用鼠标选中要保存的回答文本（连同其中的引用链接一起选中）。
3. 点工具栏上的插件图标，在弹窗里点“读取所选内容”，核对预览里的页面标题、地址、回答文本和链接。
4. 手工填写：实际提问原文（必填）、平台编号、时间窗口、题目编号、模型或产品版本（未知则填写入口特征）、
   是否登录 / 是否清除历史 / 是否联网（是 / 否 / 未知）、地域、设备、采集人。不知道的项留空或选“未知”，导出为 null。
5. 点“保存为文件”，浏览器把 JSON 文件保存到下载目录。弹窗会显示文件名、保存时间，以及建议补填的项。

文件格式见 [FORMAT.md](FORMAT.md)，虚构示例见 [examples/capture.example.json](examples/capture.example.json)。

## 导入

```sh
geo-verify collect PROJECT --adapter share --input geo-capture_engine-a_W1_Q001_20261008T020000Z.json \
  --platform engine-a --window W1 --query Q001
```

`--adapter share --input` 只解析这个本地文件，不联网。导入后的观测通道为 `browser_assist`，
`saved_at` 作为保存时间如实记录。提问原文与封存题库中的题目文本不一致时，以文件里的实际提问原文为准，并给出警告。

## 已知限制

- 选区内容取决于页面呈现：读取的是浏览器对选区给出的文字，折叠、未渲染或画在图片里的内容取不到；排版（如表格、列表符号）可能与页面看到的不同。
- 只读取页面主框架里的选区；嵌在内嵌框架里的回答、输入框里的文字取不到。
- 时间为保存时间：插件无法知道提问和回答发生的时间，不会推算或伪造。
- 平台编号、题目编号、是否登录等信息全部靠手工填写，插件不从页面上推断。
- 弹窗失去焦点（例如去页面上点击）就会关闭，已填写的内容不保留（插件不使用任何存储）；请先选中回答，再打开弹窗一次填完并保存。
- 浏览器设置页、扩展商店页等页面不允许插件运行，此时弹窗会提示无法读取。
- 本插件只在测试替身环境中验证过脚本逻辑，在真实浏览器里的表现需要人工确认。

## 测试

插件逻辑的测试随 `make check` 运行（`tests/test_extension.py`）：

- 静态检查：清单只声明两项权限、没有后台脚本和自动注入；代码文件里不出现联网、自动操作页面、读取 Cookie 或存储、指纹之类的写法；对插件实际加载的脚本另做结构检查（禁止计算属性访问、全局对象别名、反射与动态代码、字符串解码、代码里的转义，成员名与全局名走白名单），防止换一种写法绕过词表。静态检查只看写法，不能证明运行时行为。
- 行为测试：用 Node 运行 `extension/tests/` 下的 JS 测试（`node:test`，零依赖）。页面读取函数在只允许读取选区相关属性的替身对象上运行，任何越界读取或写入都会报错。

**运行测试需要 Node**（`node` 在 PATH 中，建议 20 或更新版本）；没有 Node 时测试会失败并提示，而不是跳过。也可以单独运行：

```sh
node --test "extension/tests/*.test.mjs"
```
